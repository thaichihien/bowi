# What Bowi understands

Supported: **TypeScript and JavaScript**, **Python**, **Go**, **Java**, **Kotlin** and **C#** projects, with framework support for NestJS, Express, Koa, Fastify, Hono, tRPC, React, Next.js, React Router, Angular, Vue, Nuxt, Svelte, SvelteKit, SolidJS and Astro, and for the TypeORM, Sequelize, Mongoose and Drizzle database libraries. Other TypeScript/JavaScript projects (libraries) get everything except framework-specific layers, links and hints. Python, Go, Java, Kotlin and C# projects get the same, without framework support yet. Files in other languages are still shown, grouped and never dropped, but as plain text.

## Languages

| Language                                              | Files                                                 | What Bowi does with it                                                                                                                                                                                                                            |
| ----------------------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript, TSX, JavaScript, JSX                      | `.ts` `.mts` `.cts` `.tsx` `.js` `.mjs` `.cjs` `.jsx` | Full support: changes mapped to functions, methods, classes, interfaces, types, top-level constants and test blocks; links from calls, types, imports and tests; formatting-only changes and moved code detected; unchanged callers listed; hints |
| Vue, Svelte, Astro components                         | `.vue` `.svelte` `.astro`                             | The script (Astro: the frontmatter) as TypeScript, with everything above; the markup as text, plus the components and names it uses (`<UserCard>`, `{count}`). A markup-only change is never taken for formatting                                 |
| Python | `.py` `.pyi` | Changes mapped to functions, methods, classes and module-level names (decorators included); links from calls, types and imports (relative and absolute module paths) and from `test_*.py` / `*_test.py` to the module they test; formatting-only changes (Black, Ruff) and moved code detected; unchanged callers listed; new dependencies in `requirements*.txt`, `pyproject.toml` and `Pipfile`. |
| Go | `.go` | Changes mapped to functions, methods (named after their receiver: `Server.Start`), structs, interfaces, types and package-level names; files of one package linked without imports, an import linking the whole package; `*_test.go` linked to the file it tests; `gofmt` changes are formatting; unchanged callers listed; new requirements in `go.mod`. |
| Java | `.java` | Changes mapped to classes, interfaces, enums, records, annotation types, methods and constructors (an overloaded method has its parameter types in its name: `UserService.save(User)`); files of one package linked without imports, also across `src/main` and `src/test`; links from calls, types and imports (single, static and `.*`); `*Test`, `*Tests`, `*IT` and `*IntegrationTest` linked to the class they test; reformatting is formatting; unchanged callers listed; new dependencies in `pom.xml`. |
| Kotlin | `.kt` `.kts` | As for Java (one family: Java and Kotlin files link to each other), plus objects, companion-object members as members of their class, top-level functions and properties, and extension functions (`closeQuietly(this Socket)` when overloaded); an import of a top-level function links its package; new dependencies in `build.gradle(.kts)` and `gradle/libs.versions.toml`. About one Kotlin file in twenty hits a grammar limit (for example a variable named `in1`) and is shown as text. |
| C# | `.cs` | Changes mapped to classes, structs, records, interfaces, enums, delegates, methods, constructors and properties (`user.Email` links to a changed property); names resolved through the file's namespace, the namespaces enclosing it and its `using` directives, in any file, so the parts of a partial class link to each other; `*Tests` and `*Test` linked to the class they test; reformatting is formatting; unchanged callers listed; new NuGet packages in `*.csproj` and `Directory.Packages.props`. Global and implicit usings are not followed. |
| JSON                                                  | `.json`                                               | Keys two levels deep (e.g. `dependencies.nodemailer`); `package-lock.json` summarized (new, removed and major-version dependencies)                                                                                                               |
| YAML                                                  | `.yaml` `.yml`                                        | Keys two levels deep (e.g. `jobs.build`)                                                                                                                                                                                                          |
| Markdown                                              | `.md` `.markdown`                                     | Sections by heading (e.g. `Authentication.Email verification`); re-wrapped text counts as formatting; docs join the code they mention                                                                                                             |
| Everything else (SQL, PHP, Rust, Ruby, CSS, …) |                                                       | Text only: diffed and grouped by shared names and folders, with syntax highlighting when available; no symbols or move detection. SQL support is planned                                                                                          |

Generated files are collapsed as noise, never removed: lockfiles (npm, Yarn, pnpm, Bun, Poetry, uv, Pipenv, PDM, `go.sum`), Gradle and NuGet lockfiles (`gradle.lockfile`, `packages.lock.json`), protobuf output (`*_pb2.py`, `*.pb.go`), generated Java sources (`target/generated-sources/`, `build/generated/`), C# designer and generator output (`*.Designer.cs`, `*.g.cs`, EF Core's `*ModelSnapshot.cs`), `dist/`, `*.min.js`, `*.min.css`, `*.snap`, `*.gen.ts`, `*.generated.*`, files whose header says `@generated` or `DO NOT EDIT` (Go's `// Code generated … DO NOT EDIT.`) or `<auto-generated` (C#), files marked `linguist-generated` in `.gitattributes`, and your `generated` globs. Only npm lockfiles get a dependency summary.

## Layers

Each group is split into steps by layer, and steps are read in dependency order: code before the steps that call it. When two steps do not depend on each other, the order is data shape, helpers, domain, services, API, UI, other code, configuration, tests, docs. Groups are ordered the same way: a group comes after the groups it uses, and groups that do not use each other start with the one whose code is most foundational, then the larger one.

If a folder misleads Bowi (e.g. a service under `common/` that is not a NestJS class), set its layer in [`.bowi.json`](../README.md#configuration).

### How Bowi picks a file's layer

A file's layer comes from your `.bowi.json` `layers` first, then from a framework plugin (NestJS decorators, Next.js route files, …), then from its path (the first matching row in the order test, docs, config, schema, data, domain, service, API, helpers, UI). Python and Go files follow the same rules with their own file names (`models.py`, `schemas.py`, `types.go` as data; `services.py` as services; `views.py`, `urls.py`, `routes.py`, `handlers.go` and Python `views/` and `routers/` folders as API; `utils.py`, `helpers.go` as helpers; `test_*.py`, `*_test.py`, `conftest.py`, `*_test.go` as tests; `requirements*.txt`, `setup.py`, `go.mod` as configuration), and are never UI: one that matches nothing is other code, so a FastAPI `app/` folder is not a Next.js one. Java, Kotlin and C# files follow them by class name and folder: `*Entity`, `*Repository`, `*Dto`, `*Model` and C#'s `Entities/`, `Models/`, `Repositories/` as data; `*Service`, `*ServiceImpl` and C#'s `Services/` as services; `*Controller`, `*Endpoint` and C#'s `Controllers/` as API; `*Utils`, `*Helper`, `*Extensions` and C#'s `Utilities/`, `Helpers/`, `Extensions/` as helpers; EF Core's `Migrations/` as schema; `src/test/`, `src/jvmTest/` and other `src/*Test/` folders, `*.Tests/` projects and `*Test`, `*Tests`, `*IT` files as tests; `pom.xml`, `build.gradle(.kts)`, `*.csproj`, `*.sln`, `appsettings*.json` and `application*.properties` as configuration; Android `*Activity`, `*Fragment` and `*Screen` files, `res/` layouts and Razor pages as UI. One that matches nothing is other code, never UI, so an Android `app/` module is not a web app.
